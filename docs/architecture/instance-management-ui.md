# Redis Pilot 实例管理页 — 实例组与节点操作设计

> 状态：待实现  
> 定稿日期：2026-09-01  
> 实现范围：`web/dashboard/src/`，优先复用现有 Server API，不改变 Redis Pilot 的拓扑与状态模型

本文定义 Dashboard「实例管理」页中实例组、standalone 节点、主库节点和从库节点的展示层级与操作归属。实现者应以本文作为页面行为和验收依据，避免实例组操作与节点操作继续混在同一层级。

---

## 1. 背景与问题

当前实例列表同时展示实例组行与展开后的节点行，但操作作用域没有严格区分：

- 实例组行的「查看」实际打开当前主库节点详情；
- 「备份列表」出现在实例组、主库和从库菜单中，但接口始终按实例组查询和执行；
- 主从组展开后，组行与主库行重复展示修改配置、调整规格、启停、删除等节点操作；
- 运行中的主库不可停止或删除时，仅以菜单项变灰表达，没有直接说明原因；
- `1 主 0 从` 的 replication 组因为没有从库而不能展开，视觉行为与 standalone 相似，但启停约束又不同；
- 所有三点按钮的可访问名称都是「更多操作」，无法判断操作目标。

本次调整的目标是让用户在点击前明确知道：当前操作影响整个实例组，还是只影响一个具体节点。

---

## 2. 核心设计原则

1. **实例组是父级，节点是子级。** replication 组始终显示父行，并可展开主库/从库节点。
2. **操作按真实作用域放置。** 组级接口只出现在组行，节点级接口只出现在节点行。
3. **standalone 不制造无意义层级。** standalone 只有一个节点，列表只显示一行，菜单平铺展示所有可用操作，不强加作用域分区（作用域分区只用于 replication）。
4. **角色与实例名分离。** 主从角色可能因 failover 变化，不在实例名中编码角色，UI 使用实时角色徽标。
5. **不可执行的操作必须解释原因。** 不能只靠降低透明度表达禁用状态。
6. **同一能力只保留一个入口。** 例如备份管理只能从实例组进入，不能在每个节点重复出现。

---

## 3. 术语与作用域

| 术语 | 含义 | 示例 |
|---|---|---|
| 实例组 | 对业务暴露统一接入点、共享拓扑与组级策略的逻辑对象 | `galaxy` |
| standalone 节点 | standalone 组内唯一的数据节点 | `aha-1` |
| 主库节点 | replication 组当前承担写流量的节点 | `galaxy-1` |
| 从库节点 | replication 组中复制主库数据的节点 | `galaxy-2` |
| 组级操作 | 影响组策略、拓扑、统一接入或由平台在组内自动选择节点的操作 | 备份、接入模式、故障转移 |
| 节点级操作 | 明确作用于某个具体容器/实例的操作 | 配置、规格、启停、删除节点 |

页面文案统一使用「主库」「从库」，不使用 `master` / `slave` 作为用户可见标签；代码字段继续沿用现有 `master` / `replica`。

## 4. 页面信息架构

### 4.1 列表列定义

保留当前列表的主要列：

| 列 | 实例组父行 | 节点子行 |
|---|---|---|
| 实例组 / 节点 | 组名；副文案为拓扑摘要或唯一节点名 | 角色徽标 + 节点名 + 节点规格 |
| 类型 | 缓存 / 持久化 | 留空 |
| 接入 / 拓扑 | 标准 / 读写分离；单点或 `1主 N从` | 留空 |
| 架构 / 版本 | Redis/Kvrocks 版本 | 留空 |
| 节点 / 接入点 | Proxy 业务接入地址 | 物理节点名 + Redis 端口 |
| 内存使用 | 组内节点聚合使用率 | 当前节点使用率 |
| 状态 | 组健康或拓扑状态 | 当前节点运行状态 |
| 操作 | 组操作；standalone 为平铺菜单 | 节点操作 |

### 4.2 replication 展开规则

展开能力由 `group.type === 'replication'` 决定，不能再由 `group.replicas.length > 0` 决定。

- `1 主 1 从`、`1 主 N 从`：父行可展开，依次显示当前主库和全部从库；
- `1 主 0 从`：父行仍可展开，显示主库节点，并在子区域显示「当前没有从库」提示与「添加从库」入口；
- 主库缺失或状态异常：父行仍可展开，显示现有节点和异常说明，不得因为 `master === null` 隐藏整个操作层级；
- standalone：不显示展开箭头，不渲染子行。

展开控件必须使用可聚焦的 `<button>`，设置 `aria-expanded` 与包含组名的可访问名称，例如「展开实例组 galaxy」。不能继续用仅支持鼠标点击的普通 `<div>`。

## 5. standalone 显示规则

standalone 只显示一行，不再额外渲染唯一节点子行。

示意：

```text
aha
节点：aha-1       单点 · Redis 7 · 标准接入 · 健康       [详情] [更多]
```

### 5.1 主按钮

- 文案：`详情`（全站主按钮统一文案，见 10.1）
- 行为：打开唯一节点详情；详情标题同时显示实例组名和节点名。

### 5.2 更多菜单

standalone 只有一个节点，组即节点，**不做作用域分区**。菜单平铺展示，避免给单实例强加「组管理 / 实例运维」这种对用户没有意义的层级：

```text
编辑标签
备份管理
修改配置
调整规格
停止实例 / 启动实例
────────────
删除实例
```

规则：

- 「编辑标签」「备份管理」在实现上按实例组执行，「修改配置」「调整规格」「启动/停止」按唯一节点执行，但**这一作用域差异对 standalone 用户不可见**，菜单不出现分区标题；
- 「删除实例」固定放在菜单末尾、以分隔线隔开并用红色文字（见 9.3），删除唯一节点，确认弹窗明确提示「删除后实例组 aha 也会被移除」；
- standalone 不显示「切换接入模式」「添加从库」「故障转移」。

> 注：作用域分区（组管理 / 节点运维）只在 replication 场景使用（见第 6 节），standalone 不引入该复杂度。

## 6. 主从实例组显示规则

主从采用固定的父子层级：

```text
▼ galaxy                         读写分离 · 1主1从 · 健康
  业务接入：redis-proxy:16379                         [详情] [更多]

    主库  galaxy-1               redis02:6379 · 运行中 [详情] [更多]
    从库  galaxy-2               redis03:6379 · 运行中 [详情] [更多]
```

### 6.1 实例组父行

父行只展示组级汇总信息和组级操作，不得代理当前主库执行节点操作。

主按钮：

- 文案：`详情`（全站统一文案，见 10.1；层级差异由行内角色徽标区分，不靠按钮文案）
- 默认打开实例组详情的「拓扑」页签；
- 弹窗标题以组名为主，不以当前主库节点名为主；
- 组详情内可以继续提供「拓扑」「接入」「备份」「异常」「任务」「审计」等组级信息。

更多菜单：

```text
实例组管理
  编辑标签
  备份管理
  接入设置
  添加从库
  故障转移
```

操作说明：

| 操作 | 行为 | 显示/可用条件 |
|---|---|---|
| 编辑标签 | 编辑 `group.labels` | 始终显示 |
| 备份管理 | 按 `groupName` 查询备份、立即备份、设置计划 | 始终显示；不能出现在节点菜单 |
| 接入设置 | 打开组详情「接入」页签，修改 `access_mode` | replication 组显示；无可用 auto 端口时读写分离选项禁用并解释原因 |
| 添加从库 | 打开创建实例弹窗，预选「加入已有实例组」和当前组 | replication 组显示；组正在执行互斥任务时禁用 |
| 故障转移 | 调用现有 `/instance/failover` | 至少一个健康运行从库时可用；否则显示禁用原因 |

本期不新增「一键删除实例组」能力。现有后端只有节点删除接口，主从组仍需先删除从库，再删除最后的主库。不要在前端用多个节点删除请求拼装一个看似原子的组删除操作。

### 6.2 主库节点行

主按钮：`详情`（统一文案；节点身份由行首「主库」徽标区分）

更多菜单（只保留高频运维项，见 6.4）：

```text
停止实例
────────────
删除节点
```

规则：

- 「修改配置」「调整规格」等低频操作不进节点行菜单，改由「详情」弹窗内的操作区提供（见 6.4）；
- 不显示编辑标签、备份管理、接入设置、添加从库；
- 运行中的 replication 主库不可直接停止：保留菜单项但设置 `aria-disabled="true"`，禁用原因按 9.1 的「按需展开」方式呈现「当前主库不可直接停止，请先完成故障转移」；
- 主库存在从库时不可删除：原因「主库存在从库，请先删除从库或完成拓扑调整」；
- 主库已停止、异常停止或失败时，显示「启动实例」；
- replication 组只剩 `1 主 0 从` 时允许删除最后的主库，但确认弹窗必须提示删除后实例组也会被移除。

### 6.3 从库节点行

主按钮：`详情`（统一文案；节点身份由行首「从库」徽标区分）

更多菜单（只保留高频运维项，见 6.4）：

```text
停止实例 / 启动实例
────────────
删除从库
```

规则：

- 「修改配置」「调整规格」等低频操作不进节点行菜单，改由「详情」弹窗内的操作区提供（见 6.4）；
- 不显示编辑标签、备份管理、接入设置、添加从库、故障转移；
- 运行中的从库允许停止；已停止或失败的从库允许启动；
- 允许删除从库，确认弹窗必须显示节点名、实例组名以及删除后的拓扑变化，例如 `1主2从 → 1主1从`；
- 删除最后一个从库后，父行保留 replication 类型并显示 `1主0从` 与「拓扑降级」。

### 6.4 节点行菜单只放高频项，低频操作下沉到详情

为降低列表每行的按钮/菜单密度，节点级操作按使用频率分两处呈现：

- **节点行三点菜单**：只保留高频运维项——启动/停止、删除节点。危险项（删除）固定放末尾并用分隔线隔开。
- **节点详情弹窗内的「操作」区**：承载低频项——修改配置、调整规格。

这样 `1主N从` 展开后，屏幕上每行三点菜单更短，视觉更整齐；用户需要改配置/规格时先进详情，符合这两类操作"看清当前值再改"的实际使用路径。standalone 不受此约束——它平铺展示（见 5.2），本就只有一行。

## 7. `1 主 0 从` 的特殊显示

`1 主 0 从` 仍然是 replication 组，不能降格成 standalone 样式。

```text
▼ ai                             标准 · 1主0从 · 拓扑降级
  缺少从节点，无法故障转移与读写分离               [详情] [更多]

    主库  ai                     redis01:6379 · 运行中 [详情] [更多]
    当前没有从库                                      [添加从库]
```

- 父行可展开；
- 状态显示「拓扑降级」，原因显示「缺少从节点」；
- 「添加从库」可用；
- 「故障转移」禁用，原因显示「没有可用从库」；
- 主库的「停止实例」禁用；
- 删除最后主库可用，但必须提示实例组会同时移除。

## 9. 菜单状态与反馈规范

### 9.1 禁用项

禁用项不能只使用低透明度，但原因**不常驻整行**，避免菜单被说明文字撑长撑乱。禁用项需要同时满足：

- 可见操作名称（灰化处理）；
- 名称旁有一个明确的原因触发点（如「?」/ info 图标）；
- 原因按需呈现——鼠标悬停或点击图标时以 tooltip / 展开区显示，默认收起；
- `aria-disabled="true"`（用非原生 disabled 元素承载，保证悬停与焦点事件稳定，可安全挂 tooltip）；
- 仍可获得键盘焦点，焦点落在禁用项时读屏能读出原因；
- 点击禁用项本身不关闭菜单，也不误触发操作。

示例（默认态只显示一行，原因在悬停/展开后出现）：

```text
停止实例  (?)        ← 默认只有名称 + 问号
└ 悬停/点击展开：当前主库不可直接停止，请先完成故障转移
```

由于采用 `aria-disabled` 的非原生元素（而非原生 `<button disabled>`），悬停与焦点事件在各浏览器稳定触发，因此可以放心用 tooltip 承载原因，不必把原因常驻为整行文字。

不要直接给原生 `<button disabled>` 加 tooltip，因为 disabled button 在部分浏览器中不会稳定触发悬停和焦点事件。

### 9.2 执行中

- 操作提交后，目标菜单项显示加载状态，例如「正在停止…」；
- 同一实例组的互斥写操作期间，相关组操作与节点操作均禁用；
- 操作完成后刷新实例组和节点状态；
- 异步任务提供「查看任务」入口。

### 9.3 危险操作

删除操作固定放在菜单末尾，使用红色文字并通过分隔线与普通操作隔开。确认弹窗必须展示：

- 操作对象类型：实例组、主库节点、从库节点或 standalone 实例；
- 实例组名和节点名；
- 是否清理数据；
- 对拓扑和业务接入的影响；
- 不可恢复提示。

## 10. 文案与可访问性

### 10.1 按钮文案

主按钮全站统一为 `详情`，层级与角色差异靠**行内角色徽标**（组名 / 主库 / 从库）区分，不用不同的按钮动词，避免一列里出现多种文案导致纵向扫视困难。

| 场景 | 主按钮 | 更多按钮可访问名称 |
|---|---|---|
| standalone | 详情 | `aha 更多操作` |
| replication 组 | 详情 | `实例组 galaxy 更多操作` |
| 主库节点 | 详情 | `主库 galaxy-1 更多操作` |
| 从库节点 | 详情 | `从库 galaxy-2 更多操作` |

> 主按钮虽同为「详情」，但可访问名称仍需区分（如 `实例组 galaxy 详情` / `主库 galaxy-1 详情`），保证读屏用户能判断目标；点击行为也按各自层级打开对应详情弹窗（组详情 / 节点详情）。

### 10.2 状态不能只靠颜色

健康、拓扑降级、运行中、已停止等状态必须保留可见文字。主库/从库角色同时使用文字徽标，不能只靠蓝色或灰色区分。

### 10.3 键盘行为

- 展开按钮、查看按钮、更多按钮均可通过 Tab 聚焦；
- Enter/Space 可展开或收起实例组；
- 菜单打开后焦点进入第一个菜单项；
- Escape 关闭菜单并把焦点返回三点按钮；
- 菜单项使用方向键导航；
- 点击行内复制、查看、更多操作时不能误触发父行展开。

- `isStandaloneGroup(group)`；
- `isReplicationGroup(group)`；
- `canExpandGroup(group)`；
- `groupActionsFor(group, context)`；
- `nodeActionsFor(item, group, context)`；
- `nodeRowActionsFor(item, group, context)`（只返回进节点行菜单的高频项：启停 / 删除）；
- `nodeDetailActionsFor(item, group, context)`（返回下沉到详情弹窗的低频项：修改配置 / 调整规格）；
- `operationDisabledReason(action, item, group)`。

操作显示规则应由纯函数生成，避免继续在多个 JSX 分支内复制判断。

### 11.3 复用现有接口

| UI 操作 | 现有接口/能力 |
|---|---|
| 编辑标签 | `POST /instance/labels` |
| 备份管理 | `/backup/list`、`/backup/exec`、`/backup/schedule` |
| 接入设置 | `POST /instance/access-mode` |
| 添加从库 | 复用创建实例流程，以已有组为目标 |
| 故障转移 | `POST /instance/failover` |
| 修改配置 | `POST /instance/config` |
| 调整规格 | `POST /instance/resize` |
| 启动/停止 | `POST /instance/start`、`POST /instance/stop` |
| 删除节点 | `POST /instance/delete` |

如果后端最终校验与前端预判不一致，以后端结果为准，并把返回原因直接展示给用户；前端预判只用于提前解释，不可替代服务端保护。

## 13. 验收标准

### 13.1 standalone

- [ ] 列表只显示一行，无展开箭头；
- [ ] 副文案使用「节点：实例名」，不使用「主库：实例名」；
- [ ] 菜单为平铺列表，无「组管理 / 实例运维」分区标题；
- [ ] 菜单包含编辑标签、备份管理、修改配置、调整规格、启停、删除，且删除位于末尾并以分隔线隔开、红色文字；
- [ ] 主按钮文案为「详情」；
- [ ] 删除确认明确说明实例组会同时移除。

### 13.2 `1 主 0 从`

- [ ] replication 父行可以展开；
- [ ] 展开后显示主库节点行；
- [ ] 显示「当前没有从库」和「添加从库」入口；
- [ ] 父行显示 `1主0从` 与拓扑降级原因；
- [ ] 故障转移禁用并说明没有可用从库；
- [ ] 主库停止操作禁用并说明需先故障转移。

### 13.3 `1 主 N 从`

- [ ] 父行只含组级操作；
- [ ] 主库和所有从库各显示一条节点子行；
- [ ] 主库节点菜单不再出现备份管理；
- [ ] 从库节点菜单不再出现备份管理；
- [ ] 节点行三点菜单只含启停 / 删除，修改配置、调整规格只在节点详情弹窗内出现；
- [ ] 主按钮文案统一为「详情」，主库/从库靠角色徽标区分；
- [ ] 主库停止和删除受拓扑保护并显示原因；
- [ ] 从库可以独立启停和删除；
- [ ] failover 后角色徽标按最新状态更新，节点名不变。

### 13.4 通用体验

- [ ] 每个更多按钮的 `aria-label` 包含操作对象名称和角色；
- [ ] 展开/收起可用键盘完成；
- [ ] 点击复制、查看或更多按钮不会连带展开/收起父行；
- [ ] 禁用项默认只显示灰化名称与原因触发点（?/图标），悬停或点击后才展开原因，且读屏可读，原因不常驻整行；
- [ ] 菜单只保留一个真实入口，不再在组行和节点行重复同一能力；
- [ ] 桌面端 1220px 最小表格宽度下无列错位；
- [ ] 移动端允许横向滚动，菜单不超出可视区域；
- [ ] 前端构建通过，standalone、`1主0从`、`1主1从`、`1主多从` 均有组件或端到端测试覆盖。
