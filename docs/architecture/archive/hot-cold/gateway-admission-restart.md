# Gateway 重启恢复：业务恢复与冷热操作保护分离

> 历史阶段归档：保留当时的方案与验收记录，不代表当前能力或恢复策略。现状以 [现行设计](../../hot-cold-gateway-design.md) 和 [实现进度](../../hot-cold-status.md) 为准。

2026-09-08，根据用户确认修正。本文替代 G6b-2f-2 的“dirty 就整体拒绝启动”方案。历史验证记录保留当时结果，不再代表当前行为。

## 当前原则

Gateway 是代理和冷热协调者，不是普通热写的持久数据所有者。Gateway 退出不等于 Redis 丢失，更不等于 Kvrocks 必须立即接管。普通业务继续访问权威热层，不能因为代理进程留下 dirty 就整体停服。

- dirty/clean 是本地运行诊断，不是业务准入许可。结构完整、绑定匹配的 dirty 文件允许恢复。
- 启动时先恢复已有冷热操作对应的 key 屏障，再接收业务；其他 key 正常工作。
- 普通请求丢回复：不自动重放该请求，也不永久封锁该 key。之后的 GET、新提交的 SET/INCR 可以继续执行。
- 普通请求未知结果和 dirty 均不触发分片级冷热暂停；不需要人工清除暂停标志。
- 正在冷热切换的 key：保持对应屏障和持久意图，不凭进程重启或历史 receipt 放开。
- Redis 故障、源历史改变、冷层落后，是另外的数据可用性问题；Gateway 重启不会自动回落 Kvrocks。

## 不确定请求影响什么

没有冷热操作屏障时，未知结果不保留永久逐 key 阻断条目，释放业务在途占用；同一个 key 和其他 key 都可以再申请新的冷热准备。已删除原先只会置位的 `transitionsPaused` 标志。客户端是否收到成功回复不是数据版本、同步完成或冷热切换的依据。

如果未知结果发生在已有屏障所等待的请求上，保留该操作 key 的屏障，其他 key 不受牵连。后来的普通成功回复不能替代这次操作的核查。

dirty 重启不暂停新准备，只恢复真实存在的持久操作屏障。已持久化的准备/确认操作仍沿用同一意图、同一 key，并重新检查值和源历史；不会自动重发任何业务命令。

管理状态已移除 `new_preparations_paused`，保留具体操作的 `state`。同步故障、冷确认失败仍按操作返回错误，不改变普通业务 readiness，也不新增分片级暂停状态。

允许申请准备不等于允许删除热数据。当前准备脚本原子检查类型、TTL 和当前值，只写准备标记；同步器确认的是复制流中的对应准备事件。未来真正删除/切换必须额外证明旧执行者及迟到写入不能越过切换边界，并校验当前数据版本与冷层提交位置。普通回复未知不能代替这个协议，简单新建连接/PING/等待几秒也不能提供该证明。当前未实现热删除，不将本次放开准备当作删除授权。

## 启动、停止和文件

1. 检查固定绑定、文件完整性及独占锁。恢复允许 clean 和 dirty 两种有效状态。
2. 保存本次启动记录，安装新的业务准入集合。
3. 配有准备控制器时，从持久操作文件恢复受影响 key 的屏障；全部完成后才启动 Service 请求入口。
4. 停机等待业务和管理工作线程结束。仍有未完成操作时保留 dirty，但不因此把正常停止报告为失败；没有局部操作或在途占用时可保存 clean，普通历史丢回复不妨碍正常退出。
5. 下一次启动继续恢复正常热层访问和局部屏障，不通过读取旧 receipt 自动解除操作。

文件仍使用有界、带校验的固定长度记录和私有权限要求。状态文件缺失/损坏、绑定不匹配、同时存在另一个文件所有者仍报错，这是状态或配置无法安全解释，不是“发现 dirty 就停服”。

不能通过关闭准备控制器配置跳过已有操作：发现持久操作文件却没有相应恢复配置时拒绝该配置。损坏操作记录无法识别受影响 key 的降级流程还未实现。

## 已验证与边界

测试已改为验证：

- 普通 INCR 执行后丢回复，后续 GET 读到结果，新 INCR 可继续执行，原请求不被重放。
- 没有冷热操作的未知结果不累积永久 key 条目，也不暂停新的准备。
- 测试子进程被强杀后，dirty 文件可恢复并允许普通准入和新的准备预留。
- 实际 Service 从 dirty 状态启动后可以读普通 key，并执行新的准备。
- 模拟后端执行 INCR 后丢回复，同 key/其他 key 的新准备与确认均成功，INCR 只执行一次。
- 持久操作恢复后，其 key 仍被拒绝，其他 key 可访问；受保护退出不再返回全局 unsafe 错误。
- 缺失/损坏文件、绑定变更、跳过操作恢复配置仍被拒绝。

上一轮验证：本地专项 race 三轮通过；相关包 race 通过。真实 Redis 7.2.5 / Kvrocks 2.15.0 新旧确认用例各三轮通过，联合测试已实际验证重启后操作 key 阻断、其他 key 可读。[上一轮验证记录](../../benchmarks/gateway-recovery-correction-20260908.log)包含运行命令、二进制摘要及首次复用环境不满足空库条件的记录；其中“暂停新转换”是当时行为，已被本次修正替代。本次移除全局暂停的验证另见 [验证记录](../../benchmarks/gateway-no-global-pause-20260908.log)。

这仍是单 Gateway/单绑定的内部实验接线，没有公开 YAML 开关。未实现热删除、回温、完整 Redis 语义、分布式 fencing 或 Cluster 迁移。
