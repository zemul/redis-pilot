## 捕获暂停与恢复

每次写入 snapshot 或 command 前，先检查逻辑日志容量，再对日志目录的文件描述符执行 Fstatfs，计算普通用户可用块数 × 块大小。计算检查无效块大小和整数溢出；采样失败按无法确认安全空间处理。

写入预算包含编码后记录、新段头，以及 bootstrap/轮转时的临时 manifest；额外保留块分配余量。通过预检并不保证真实 write/fsync 成功：其他进程共享空间、用户 quota、inode、COW 与文件系统元数据仍可能导致失败。

原型默认参数均可通过内部 `syncResourcePolicy` 明确传入，未接 service YAML/API，不代表生产推荐值：

| 项目 | 默认值 | 含义 |
| --- | --- | --- |
| 磁盘捕获保留量 | 64 MiB | 追加后仍应留有此余量 |
| 磁盘恢复水位 | 128 MiB | 已暂停时恢复需达到更高可用量 |
| 未确认复制字节上限 | 64 MiB | 预测追加后超过此值暂停 |
| 未确认复制字节恢复水位 | 32 MiB | 已暂停时下降到此值才解除 |
| 同时活跃日志视图 | 4 | 避免无限复制文件描述符、长期固定旧段 |
| 单次清理目录项上限 | 4096 | 超限不删除，要求明确调整或处理 |

磁盘比较还要扣除本次写入预算，所以不是仅判断可用空间是否超过 64/128 MiB。配置的最小保留量不能小于最大 manifest 加块余量；但这不是预分配的保留文件，不能承诺磁盘彻底满时 GC 仍一定可写。

暂停发生在任何记录写入前：返回可识别压力错误，不推进 durable position，不 poison 当前日志，不把失败记录算入 Redis ACK。原有逻辑容量不足仍返回容量错误，与物理可用量压力分开。

复制连接随本次捕获调用退出；调用方可以观察 `resourceStatus`，待条件恢复后显式再次调用捕获，从已 fsync 位置 PSYNC 续传。**本轮没有自动重连、退避、告警或后台调度。** 暂停过久导致 Redis backlog 丢失时，仍拒绝自动 FULLRESYNC 覆盖冷层。

真实写入或 fsync 失败与“写前压力拒绝”不同：前者保持既有 poison → 关闭/重开的不确定结果处理，不能自动重发。

## 积压的精确定义

`UnconfirmedBytes` 是当前捕获 offset 减去本地 manifest 最后持久化的冷层 `Confirmed` offset；没有 Confirmed 时减去初始 Base offset。它计的是**源复制流字节**，不是 JSON 日志长度、磁盘物理占用、key 数、时间延迟或精确的冷层未应用字节数。

冷层可能已经应用完成，但本地尚未执行确认/回收。因此当前统计有意偏保守：单独 `applySegments` 不释放积压阈值；只有通过冷层 pending/after 校验并持久化 confirmed 的 `pruneSegments` 才会释放。

初始 RDB 不计入增量 offset 差，仍受快照大小、逻辑日志容量和物理空间检查限制。

不因捕获暂停而禁止冷层应用、GC 或孤儿清理，避免阻断释放资源的路径。GC 仍必须遵守先持久化 manifest、再删旧段的顺序；若实际无法写 manifest，不能跳过它直接删日志。

## 视图预算

每个成功建立的固定视图登记一个名额，超过上限返回明确错误；close 只释放一次，构造中途失败关闭部分描述符且不占名额。journal 关闭后，旧视图仍保留独立段和 LOCK 描述符，可以完成读取再释放。

不通过超时强关正在使用的视图。调用方必须及时关闭；旧视图持有已 unlink 的段时，空间未必释放。本轮不报告精确 pinned bytes，真实可用量以再次 Fstatfs 为准，不能把逻辑回收量提前计为磁盘释放量。

名额限制不等于操作系统文件描述符总预算；单个视图仍会为保留段复制描述符，失败时回收已打开部分。同一视图的读取与 close 必须由调用方串行，不能一边读一边强制关闭；重复/并发 close 本身保证只释放一次名额。

## 崩溃孤儿清理

`cleanupOrphans` 是显式操作，open 不自动删除恢复证据。它要求日志目录专用、当前用户拥有、所有合法写入者遵守 LOCK；这不是对抗同 UID 恶意目录修改者的安全边界。

清理首先验证当前磁盘 manifest 的 CRC、规范编码与身份、保留边界、段列表，允许 active 段的内存尾部比 manifest 已发布前缀更新，并验证该前缀。anchor 原文与 base 摘要重新核验，引用文件和 LOCK 的路径/打开描述符身份核对。manifest 缺失或恢复证据不一致时停止，不猜测清理。

使用独立目录描述符进行有界完整预扫描，不复用共享目录偏移。超出目录项上限或预扫描期间取消时不删任何文件。

只考虑专用命名空间内严格的 `anchor-` / `segment-` / `manifest-` 加 32 位小写十六进制 ID，排除当前引用文件、manifest 和 LOCK。候选必须是当前 UID、权限 0600、单硬链接的普通文件；未知文件、符号链接、硬链接、目录或其他不安全对象保留并计入 skipped，不递归。

删除前重新核对 inode/设备/大小/权限等身份，然后用目录相对路径逐个 unlink，最后 fsync 目录。进入删除阶段后取消或失败，尽力同步已经发生的删除，poison 当前句柄；重开后可再次清理剩余孤儿。此操作不改 checkpoint、confirmed 或 ACK。

返回 `RemovedFiles`、`RemovedBytes` 和 `SkippedFiles`。RemovedBytes 只是删除文件的逻辑长度之和，不表示真实磁盘一定释放相同字节。

## 验证

本地测试分别位于 `sync_resources_test.go` 与 `sync_orphans_test.go`，覆盖水位/滞回、采样失败、写前拒绝不改变日志、确认前后积压、视图生命周期、精确孤儿清理、损坏证据拒绝和中途故障恢复。真实本地 Redis 验证压力导致捕获中断后显式 PSYNC 续传。

真实 Kvrocks 验证在原分段实验上增加两项资源用例，以及强杀 GC 子进程后清理真实遗留文件再恢复。低空间用例注入可用字节采样值，**没有实际填满开发机磁盘**；冷层应用/确认/恢复使用真实 Kvrocks 2.15.0。测试范围不包括主机断电或真实 quota/inode 耗尽。

最终结果与环境收尾见 [执行记录](../../benchmarks/g6-resources-20260908.log)。

最终验证：资源/孤儿测试三轮 race 通过；网关全包 race、项目全量测试和 vet 通过；Linux 资源/清理单测通过；真实 Kvrocks 11 个集成用例连续三轮通过。测试发现并修复了恢复积压阈值为 0 时无法直接续传的边界，最终回归已覆盖。

redis03 隔离实验容器已停止，合成测试 key 已清理并验证空库，既有实例和 Agent 保持运行。未部署 Gateway/Server；本轮新增 G6a-7 改动尚未提交，前序 G6a-1～6 已提交。
