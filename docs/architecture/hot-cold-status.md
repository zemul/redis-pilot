更新：2026-09-09；按当前工作区代码核对，包含尚未提交的修改，不等于开发机已经部署。设计契约见 [现行设计](hot-cold-gateway-design.md)，部署范围见 [部署运维](gateway-deployment.md)。

## 当前能力清单

| 能力 | 状态 | 具体范围与缺口 |
| --- | --- | --- |
| Gateway 转发 | 可运行的开发服务 | 固定单 Redis 后端、RESP2、独立前后端认证、Pipeline 保序、超时/预算/指标；loopback 监听，非 Cluster |
| 命令转发 | 有限白名单 | GET/SET/INCR 等；不支持用户 Lua、事务、订阅；转发范围大于冷热回放范围 |
| 独立同步器 | 可运行的隔离服务 | RDB/PSYNC、本地分段日志、应用进度、受限重试/恢复、静态 1～8 任务；限定隔离端点和独占冷 DB |
| 冷层回放 | 受限实现 | 无 TTL String；普通 SET、单 key DEL、INCR；非幂等恢复依赖 pending、前后值、checkpoint 和事务核对 |
| 控制面 | 最小登记与观测 | Gateway 草稿/心跳；同步任务固定归属、进度上报；无自动分配、配置应用闭环或 Proxy 切流 |
| 准备与冷确认 | 内部实验接线 | 实际 Service/Pipeline 屏障、持久意图、内部标记、同步器 HTTP 确认；无公开冷热配置入口 |

| 操作正常收尾与自动恢复 | 热访问与冷收尾已分离 | 准备默认 30 秒无人继续后发起持久收尾；核对保留的源标记后先释放单 key 屏障，冷收尾后台继续；源标记回收和正式删除的取消协议未实现 |
| 准备标记增长控制 | 新协议内部可选 | `BoundedMarkers` 模式每任务固定一个标记，前一操作冷收尾完成后原子覆盖；递增编号和前驱匹配拒绝迟到脚本；默认旧模式未切换，旧标记未删除 |
| 热副本移除 | 只有记录格式/识别实验 | 尚未接正式删除、冷层跳过、位置发布、操作回收 |
| 冷读/回温 | 未实现 | 驻留判断、冷查、装回、并发写协调和旧值防复活待做 |
| 自动降冷 | 未实现 | 内存水位、LRU/LFU 候选、批量限速、冷热抖动控制待做 |
| 更多语义 | 未实现 | TTL、复杂类型、多 key 原子语义、事务和用户 Lua；最终支持清单待定 |
| Cluster/高可用 | 未实现于冷热链路 | slot/重定向、动态任务、扩容/切主、分布式归属和旧执行者隔离待做 |
| 性能与长期稳定性 | 未完成验收 | 已有隔离短测试，不代表生产热写延迟、同步吞吐、内存收益或长测通过 |

## 当前交付：保留热数据的准备收尾

这是既有基础上的下一项能力，不是重新从第一阶段开发。先在现有单分片、无 TTL String 范围内打通；本项不开放热副本删除，也不宣称完成冷热产品。

2026-09-09：准备等待/只读检查等前置失败，在尚未开始持久化意图且未派发准备时自动撤销。已持久化操作新增内部 `/internal/v1/hot-preparation/finish`：表示保留热数据结束本次准备，不是删除授权，不是降冷成功。

已实现路径：

- Gateway 先持久化收尾意图，必要时重试准备/确认，再调用同步器。后台退避重试，客户端断开、Gateway 重启后仍继续已有收尾请求。
- 未显式请求收尾的操作，控制器从持久操作接入起默认等待 30 秒后自动持久化收尾意图；重复准备/确认不延长当前计时。重启恢复未完成操作时重新安排 30 秒兜底，不恢复原来的绝对截止时间。已持久化收尾请求仍直接进入重试。该时间只控制内部实验兜底，不是生产降冷频率，也不是最长阻挡时间。
- 同步器用一条事务内 MSET 原子提交准备标记对应的 checkpoint、控制型 pending 和终态回执；不再次执行业务 INCR，不删除热数据。
- 同步器持久化本地终态并恢复后续应用；若冷层已提交而本地终态尚未写入，重启后核对精确回执及日志进度恢复。
- Gateway 持久收尾意图后，核对 Redis 复制历史、noeviction、准备标记精确内容及无 TTL；缺少有效标记时只在原准备条件仍成立时补准备，再核对。核对成功即释放匹配 key 屏障，进入 `hot_available_sync_pending`，冷确认在后台继续。旧脚本遇保留标记只能无操作返回或拒绝，不会再次产生准备事件。
- 热访问释放不持久伪造冷层成功；Gateway 重启先恢复保护，再核对源标记并释放。冷收尾成功后才清理收尾意图、结束当前任务操作并接受下一次转换；只释放普通业务，不放开下一次降冷。冷确认不再重新准备，也不会把恢复访问后的新值写回成旧值。
- 本地操作文件原子替换，保留最后一次操作；完整但落盘结果不确定的帧可重开、验证、再次 fsync，损坏记录不盲目解锁。

尚未完成，不能视为整项产品验收通过：

1. 源 Redis 不可达、历史改变、准备标记损坏或无法补准备时仍不能核对并释放；不能声称“超时就一定恢复访问”。已核对源标记的保留热数据路径不等待冷确认，但不适用于未来已经发出热删除的操作。仍要求独占源入口、标记不被外部删除、noeviction；切主隔离未验收。
2. 默认 v1 每操作准备标记仍保留且随操作数增长。新增 v2 内部可选模式复用一个固定标记，不做 DEL；只支持新建、独占的协议环境，已有 v1 操作目录不能直接切换。旧脚本隔离、旧标记迁移清理、生产编号分配和公开配置仍待实现。原子替换遇进程崩溃时的临时文件回收也待补。
3. 复制历史改变、记录损坏、资源耗尽与同步任务终止后的恢复仍有边界；不是任意故障都已自动修复。
4. 无热副本删除、冷读、回温、TTL 或 Cluster 验收；入口仍仅内部实验接线，不开放公共配置。

## 后续按结果推进

| 顺序 | 交付结果 |
| --- | --- |
| 当前收口 | 新协议接入策略、旧协议停用和旧标记迁移清理；不影响先在新隔离环境验证业务闭环 |
| 随后 | 手动指定 key 的降冷、冷读、回温与再次写入完整闭环；此前确定 Cluster 同 slot 标记布局 |
| 自动化 | 内存水位触发、候选选择、批量限速；真正降低热层内存占用 |
| 语义扩展 | 先 TTL 与约定常见命令，再逐类扩展；每类独立验收 |
| Cluster 接入 | slot 路由、动态任务、扩容/切主、控制面配置与流量接入 |
| 可用性与成本验收 | 常见故障自动恢复、长期运行、热写尾延迟、同步吞吐、资源与成本 |

不以小阶段编号衡量产品完成度；不预先承诺剩余提交次数。每次功能完成更新本清单，不新增一篇阶段架构文档。
