# Redis Pilot 线上部署资源申请

## 一、服务器资源

### 控制节点（2台）

- 用途：运行管理服务（Server、xDS 控制面、Envoy 代理、keepalived 高可用）
- 规格：4核 CPU / 8G 内存 / 50G 系统盘
- 可用区：分布在 2 个不同可用区，各 1 台
- 操作系统：Linux x86_64（CentOS 7+ / Rocky 8+）

### 数据节点（3台）

- 用途：运行 Redis/Kvrocks 实例、Agent 管理进程、Sentinel 哨兵
- 规格：8核 CPU / 内存待定 / 50G 系统盘 / 500G SSD 数据盘（挂载 /data）
- 可用区：分布在 3 个不同可用区，各 1 台
- 操作系统：Linux x86_64（CentOS 7+ / Rocky 8+）

### 合计

- 服务器：5 台
- CPU：合计 32 核
- 内存：16G（控制节点）+ 数据节点待定
- 磁盘：系统盘 250G + 数据盘 1.5T SSD

---

## 二、网络资源

- VIP（虚拟 IP）：1 个，用于控制面高可用浮动，业务和管理流量统一入口
- 内网互通：控制节点与数据节点之间网络互通，延迟 < 1ms
- 安全组/防火墙规则：
  - 控制节点对外开放 8080（管理 API）、16379-16619（Redis 代理，面向业务应用）
  - 数据节点仅对控制节点开放 8400（Agent）、26379（Sentinel）、6379-6499（Redis 实例）
  - 控制节点 A 与 B 之间开放 VRRP 协议（协议号 112）和 18000（xDS）

---

## 三、每台服务器需要部署的内容

### 控制节点 A（主节点）

1. redis-server — 管理服务主进程（二进制 + systemd 托管）
2. redis-pilot-xds — Envoy xDS 控制面（二进制 + systemd 托管）
3. Envoy — Redis 代理（Podman 容器，host 网络模式）
4. keepalived — VIP 高可用（系统包 + systemd，角色 MASTER）
5. rsync 定时任务 — 每分钟同步状态文件到控制节点 B（cron）
6. 系统包：podman、keepalived、rsync

### 控制节点 B（备节点）

1. redis-server — 管理服务冷备（二进制 + systemd，开机自启但正常不运行，故障时自动拉起）
2. redis-pilot-xds — Envoy xDS 控制面（二进制 + systemd 托管，常驻运行）
3. Envoy — Redis 代理（Podman 容器，host 网络模式，常驻运行）
4. keepalived — VIP 高可用（系统包 + systemd，角色 BACKUP）
5. 系统包：podman、keepalived

### 数据节点（3 台，每台相同）

1. redis-agent — 容器管理 Agent（二进制 + systemd 托管）
2. Redis Sentinel — 哨兵（Podman 容器，host 网络模式）
3. Redis/Kvrocks 实例 — 业务数据（由 Agent 通过 Podman 动态创建管理）
4. 系统包：podman

### 运维机器（可复用现有跳板机）

1. redis-tool — 命令行管理工具（放置一个二进制即可）

## 四、容器镜像（需提前拉取或推送到内网镜像仓库）

- docker.io/envoyproxy/envoy:v1.32-latest — Envoy 代理，部署到控制节点
- docker.io/redis:7 — Redis 7 实例 + Sentinel，部署到数据节点
- docker.io/redis:6.2 — Redis 6.2 实例（按需），部署到数据节点
- docker.io/redis:5 — Redis 5 实例（按需），部署到数据节点
- docker.io/apache/kvrocks:2.15.0 — Kvrocks 实例（按需），部署到数据节点

---

## 五、其他依赖

- Go 1.25+ 编译环境（编译机器，用于构建二进制，不需要在线上服务器安装）
- SSH 免密配置：控制节点 A 到控制节点 B 的免密登录（rsync 状态同步用）
- 2 个 Bearer Token：Server 认证 Token + Agent 认证 Token（内部生成，无外部依赖）
